## Quick facts

- **Main agent**: `~/.pi/agent` (Pi's default home). `~/.local/bin/pi` explicitly sets `PI_CODING_AGENT_DIR` and the working directory to this home, sources its `.env`, pins Node v24.21.0, and reads its `default-model.json`. - **Package on COS**: `npm:@llblab/pi-telegram` (Telegram surfaces).

COS settings live in `agent/settings.json`; the home is `~/.pi/agent`. There is no nested
agent home since the 2026-11-18 flatten.

## Routing (COS only)

A user message can be answered without a model turn:

1. **mode-switch** — `pi-config get/use promptBuild` (off unless `modeSwitch.enabled`).
2. **JEV** — `jev-classifier/` (submodule; `classify.py`). Key: `jev-classifier/.env` (`TYPESAFE_API_KEY`).
3. **calendar / reminder nodes** — `decision-nodes/calendar/` and `decision-nodes/reminder/` (Python). Reminder writer is exclusive: `store` (`reminders.jsonl` + calendar) or `tasks` (`gog tasks` on the Reminders list). Fail-open. Only COS loads these hooks. A sibling that loads them double-writes `reminders.jsonl`.

JEV details: `docs/pi-state-of-jev.md`.

## Sync: one writer each, on purpose

Two mechanisms touch the tree and that is deliberate, recorded here so nobody "fixes" it twice:

| When | Who | Does |
| --- | --- | --- |
| session start | `scripts/pre-sync.sh` in both launchers (debounced 120 s) | `git pull --ff-only`; loud when the clone is ahead/behind |
| session end | `extensions/auto-sync.ts` | commits the working tree and pushes |

The launcher pull is the deterministic read at the boundary; the extension is the write at the
end. Neither replaces the other, and a `diverged` warning from either is a real signal, not
noise. Decided 2026-11-28 (INBOX "pre-start pull duplicates auto-sync").

## Dashboards and how they start

| Port | What | How it starts |
| --- | --- | --- |
| 8786 | Project site | `pi-site.service` (`scripts/serve-site.sh` → `control/server.ts`), both hosts. Settings, host switches, and pages `/cos/`, `/web-master/`, `/tasks/` forwarded to the ports below |
| 8787 | COS usage | `npm run dashboard` or `:8786` Start. Also at `:8786/cos/` |
| 8788 | image-describer API | same |
| 5173 | image-describer page | Vite; linked from `:8786`, not forwarded. Also the leftover bash helper |
| 8789 | web-master usage | `npm run dashboard` or `:8786` Start. Also at `:8786/web-master/` |
| 8790 | unused | keep-agent was removed 2026-11-07; do not restore a dashboard here |
| 8791 | tasks-agent usage | `npm run dashboard` or `:8786` Start. Also at `:8786/tasks/` |

8786 is localhost-on-the-laptop and tailnet-on-the-VPS. `PI_SITE_BIND` in the optional machine-local `~/.config/pi-site.env` decides the bind, so one tracked unit serves both: the laptop keeps `127.0.0.1`, the VPS binds `100.85.79.17` and the phone opens `http://100.85.79.17:8786/settings` with no tunnel. That exposure is the tailnet only — the VPS's own `127.0.0.1:8786` is closed.

When `PI_SITE_TOKEN` is set (the VPS), every path needs that token: open `…/?k=<token>` once per browser and the site sets an HttpOnly `pi_site` cookie; anything else gets 401, with a one-field prompt for a browser and JSON for `/api/`. One shared secret, no accounts — rotate the line in `~/.config/pi-site.env` and restart `pi-site.service` to revoke every browser at once. No token configured (the laptop) means an open localhost page, deliberately.

The three usage pages use relative asset and API URLs, so the same files work on their own port and under 8786.

Host switches on `/settings` are not gates. They are split by host:

| Section | Switch | Writes | Takes effect |
| --- | --- | --- | --- |
| This host | Speak laptop answers | `PI_SPEECH_TUI` in `~/.config/pi-speech.env` | next answer (extension reads it per turn); shared with `/speech`, newest write wins |
| This host | Listen for Hey Pamela | `wakewordctl` | immediately |
| This host | Telegram reply mode | read-only `voice.replyMode` | the bridge reads it at startup, so the page never claims to change it live |
| VPS | Speak Telegram voice notes | `PI_SPEECH_TELEGRAM` in the VPS `~/.config/pi-speech.env`, over ssh | next reply (`speak.sh` exits 5 → the bridge sends text) |

On the VPS itself the second section reads locally (its own `telegram.json` marks it as the bridge owner). Image describer is a link to `:5173`.

`xtra/bash-system-scripts/start-dashboards.sh` is a **hand-run leftover**. It starts 8787, 8788, 8789, 5173 only. It is not an agent list. See `xtra/xtra-info.md`.

There is no `~/.pi/html` dashboard on `:3000` in this tree. Token usage is the per-agent ledgers above.
