# Input Phrase Append — Setup & Implementation Report

**Date:** 2026-11-07
**System:** Laptop `pmpmt-ThinkPad-T15-Gen-2i` (Ubuntu, kernel 7.0.0-38-generic, Pi v1.4.0, Node v24.21.0 via nvm); model on the live turn `deepseek` / `deepseek-flash`
**Location:** hook `~/.pi/agent/cos-orchestrator-agent/extensions/input-phrase/index.ts`; lines `src/input-phrase.ts`; reader `src/global-config.ts` (`agentModesConfigPath`, `readInputPhrase`); tests `test/input-phrase.test.ts`; load order `settings.json`; phrases `~/.pi/agent-modes-config.json` (beside `~/.pi/config.json`)

---

## Problem

`~/.pi/config.json` had an `inputPhrase.append1` string and nothing read it. The goal was to append that string, as extra lines, to each user message before the cos-orchestrator turn. The model should see the typed text and the extra lines as one user message.

The section then grew two alternative options, `normal` and `advanced`, each with its own `enabled` flag and `phrase`. A section that looks on while every option is off, or while two options are on, had to fail in the open instead of silently appending the wrong lines. The section was then moved out of `config.json` into its own file beside it.

---

## Investigation / Root Cause

The other input gates (`less-than-input-words`, `input-contains-path`, `input-contains-url`, `input-contains-email`) do not rewrite the user text. On `input` they print true or false. On `before_agent_start` they inject a hidden labeled block. That block is a separate custom message. It is not lines added to the user's own text.

Pi's `input` hook is the place that rewrites the submitted string. In `@earendil-works/pi-coding-agent` `dist/core/agent-session.js`, `prompt()` runs extension commands that start with `/` first, then `emitInput`. A handler may return `{ action: "transform", text }`. Handlers chain in `settings.json` load order. Skill and prompt-template expansion run after that transform, so a trailing line on `/skill:…` would break the command name. `source === "extension"` is how extension-sent prompts are marked.

`readEnabledSection` in `src/global-config.ts` already returns null unless `enabled` is boolean `true`. A string `"true"` stays off. `globalConfigPath()` resolves to `~/.pi/config.json` via `repoRoot(env)/../config.json`. The new file uses the same directory with a different name.

## Architecture / Design Decisions

### 1. Rewrite the user message, do not inject a hidden block

| Option | Verdict |
| --- | --- |
| `before_agent_start` custom message, `display: false` | **rejected** — the model sees a side block. The user message itself is unchanged. |
| `input` returning `{ action: "transform", text }` | **chosen** — the extra lines are the end of the user message the turn stores and sends. |

### 2. The section is on only when exactly one option is on

`append1` has no flag of its own. `normal` and `advanced` are alternatives (a single sentence, or a brief explanation). They live in one list, `inputPhraseOptions`, currently `["normal", "advanced"]`. A later alternative is another name on that list. The check counts how many of those entries have `enabled === true`.

| Section `enabled` | Options on | Result |
| --- | --- | --- |
| not boolean `true`, or file missing | any | append nothing, print nothing |
| `true` | exactly one | append `append1` whenever it is a string, including `""`, then that option's `phrase`. A phrase that trims to `""` is kept only when that option's `allowBlank` is boolean `true` |
| `true` | zero | append nothing, print `inputPhrase: enabled but no option is enabled` |
| `true` | more than one | append nothing, print `inputPhrase: normal and advanced are both enabled` (the on names, joined with ` and `) |

A conflict does not append `append1` either. An enabled section with no selected option must not look like a successful append. Only boolean `true` counts, so `"true"` does not turn an option on and does not count toward the conflict of two.

### 2b. `allowBlank` is per option. `append1` is not checked

Each option entry (`normal`, `advanced`, and any name added to `inputPhraseOptions` later) has `allowBlank`. It applies only to that entry's `phrase`.

| Value | Blank option `phrase` (`""` or whitespace) |
| --- | --- |
| boolean `true` | appended as a blank line |
| missing, `false`, or the string `"true"` | left out |

`append1` does not read `allowBlank`. Any string is appended, including `""` and a whitespace-only string (trimmed to a blank line). A non-string `append1` is left out. `appendInputPhrase` keeps a blank entry as its own line. It no longer drops blank lines.

### 3. Load after the gates that classify the original words

The extension is registered after `calendar-node`, `reminder-node`, and the four input gates, and before `secret-scrubber`. Those earlier `input` handlers still see the typed text. A turn they mark `handled` never reaches this hook. `before_agent_start` still sees the combined prompt, so the hidden word-count, path, URL, and email lines are computed on the text that includes the phrases. The on-screen true/false lines stay on the original text.

Skipped inputs: `source === "extension"`, and any text that starts with `/`.

### 4. Phrases live beside `config.json`, not inside it

| File | What it holds |
| --- | --- |
| `~/.pi/config.json` | The existing gates: word count, path, URL, email, calendar, reminder. `inputPhrase` was removed. |
| `~/.pi/agent-modes-config.json` | The `inputPhrase` section only. `readInputPhrase` opens this file. The same section written into `config.json` is ignored. |

`agentModesConfigPath()` is `path.resolve(repoRoot(env), "..", "agent-modes-config.json")`.

## Implementation

### Phase 1 — section, lines, hook

`src/input-phrase.ts` holds `inputPhraseOptions`, `appendInputPhrase`, `inputPhraseApplies`, and `inputPhraseFromSection`. `appendInputPhrase` strips trailing whitespace on the user text and trims each phrase. Internal newlines in a phrase stay. A blank entry stays a blank line. The first phrase starts on the next line.

`readInputPhrase` in `src/global-config.ts` calls `readEnabledSection("inputPhrase", env, agentModesConfigPath(env))`. `readEnabledSection` takes that path as an optional third argument and still defaults to `config.json`, so the other gates are unchanged.

`extensions/input-phrase/index.ts` registers `registerInputPhrase` on `input`. A conflict is printed with `ctx.ui.notify` in the TUI and stdout otherwise, then the handler returns `{ action: "continue" }`. Otherwise it returns `{ action: "transform", text }`.

With the section on, `append1` set, and only `normal` on, `hello` is sent as:

```text
hello
Congratulate me for my 31st birthday
respond in a single sentence
```

### Phase 2 — own file

The section was cut from `config.json` and written to `~/.pi/agent-modes-config.json`. The extension comment and the reader both name that file.

### Phase 3 — `allowBlank`

`allowBlank: true` was added on `normal` and on `advanced`. `optionPhrase` reads it from whichever option is the one enabled entry. `append1` is pushed whenever `typeof record.append1 === "string"`, before that check.

The modes file at the end of the session:

```json
{
  "inputPhrase": {
    "enabled": true,
    "append1": "Congratulate me for my 31st birthday",
    "normal": { "enabled": false, "allowBlank": true, "phrase": "respond in a single sentence" },
    "advanced": { "enabled": true, "allowBlank": true, "phrase": "" }
  }
}
```

`advanced` is the option that is on and its phrase is empty, so a later turn appends the birthday line and then a blank line. The modes file is read on each input.

### Verification

```text
node --experimental-strip-types --test --test-timeout=20000 test/input-phrase.test.ts
# 12 tests, pass 12

./node_modules/typescript/bin/tsc --noEmit
# exit 0
```

The tests cover line order, slash and extension skips, a missing file, a missing section, `enabled` false and the string `"true"`, exactly one option, zero options, both options, a string `"true"` beside a real `true`, a blank `append1` still appended, a blank option phrase kept only when `allowBlank` is boolean `true`, and a section that exists only in `config.json` (stays off).

### Live turn

After a restart, `pi` was already running on `deepseek-flash`. The modes file at that moment had `inputPhrase.enabled` true, `append1` set, `normal.enabled` false, and `advanced.enabled` true with `phrase` `""`. Exactly one option was on and its phrase was blank, so the only extra line was `append1`.

The typed message was `hi.`. The turn stored:

```text
hi.
Congratulate me for my 31st birthday
```

DeepSeek returned `500` `internal_error` three times (`request_id` `ef72f8b8-e92a-4e16-91ca-96cfb995489c`, `7c455b7c-d4bb-44c0-ad49-33f9cf80c8f1`, `3d6db88b-18aa-4f18-83b1-6fb3df1e701c`). Pi retried. The later call succeeded (`↑9.2k ↓158`). The thinking block and the reply both treated the message as a birthday congratulation. A bad append would surface as `400`, not three `500`s with different request ids. At that moment a blank option phrase was still dropped, so the empty `advanced.phrase` added no second line. Phase 3 changed that: with `allowBlank: true` the same empty phrase is now a blank line. A running `pi` keeps the extension list from startup, so this hook is absent until the next start. The modes file itself is read on each input.
