# Pi Laptop Backup Tool — Setup & Integration Report

**Date:** 2026-07-13
**System:** Ubuntu 24.04, Python 3.12.3
**Location:** `~/.pi/apps-scripts/backup_laptop_tool/`

---

## Problem

An existing backup script (originally built for an always-on VPS) needed to be adapted for a laptop environment. The old setup used a recurring systemd timer (every 1–24 hours) with a VPS-appropriate working directory — neither suited a laptop that goes to sleep and wakes on demand. Additionally, credentials were scattered across a local `.env` file inside the tool directory rather than the centralized `~/.pi/agent/.env` secrets file.

The goal: a boot-triggered backup of `~/.pi` configurations to Google Drive, with a web dashboard for settings and manual triggers.

## What We Changed

### 1. Virtual Environment

No venv existed at the new location. Created one and installed all dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Dependencies:** `python-dotenv`, `google-auth`, `google-auth-oauthlib`, `google-auth-httplib2`, `google-api-python-client`

### 2. Centralized Secrets

Moved Google OAuth credentials and Drive config from the tool's local `.env` into the centralized `~/.pi/agent/.env`:

| Key | Value |
|-----|-------|
| `GOOGLE_CLIENT_ID` | OAuth 2.0 client ID (Desktop app) |
| `GOOGLE_CLIENT_SECRET` | OAuth 2.0 client secret |
| `GDRIVE_BACKUPS_FOLDER` | `backups` |
| `RETENTION_COUNT` | `5` |
| `USE_HOSTNAME_SUBFOLDER` | `true` |
| `TOKEN_FILE` | `gdrive_token.json` |

**Modified `config.py`:** Changed `load_dotenv()` target from local repo root to `Path.home() / ".pi" / "agent" / ".env"`. Removed unused `REPO_ROOT` variable. Deleted the local `.env` file from the tool directory.

### 3. Blacklist Cleanup

Removed stale entries from `backup_config.json`:
- Removed: `/home/pmpmt/Documents/All Documents/cursor_scripts_python/code_arquive` (VPS-only path)
- Kept: `.git`, `venv`, `.venv`, `__pycache__`, `node_modules`, `.mypy_cache`, `.pytest_cache`, `.backup_PC_cache`

### 4. Cache Relocation

Moved the local archive cache from `~/.pi/.backup_PC_cache/` into the tool's own directory:

- **Before:** `WorkingDirectory / .backup_PC_cache` (inside the backed-up tree)
- **After:** `backup_laptop_tool / .backup_PC_cache` (self-contained)

Modified `main.py` to compute `CACHE_DIR` from the module path using `Path(__file__).resolve().parent.parent.parent`, passed explicitly to `create_snapshot_archive()` and `cleanup_old_cache_files()`.

### 5. Google Account Switch

Changed from `pjhq2025@gmail.com` to `neopmpmtj@gmail.com` (which has extra Google storage). Required:

- Delete existing `gdrive_token.json`
- Create a new Google Cloud Console OAuth 2.0 Desktop app
- Run `BACKUP_INTERACTIVE=1` to re-authorize
- Hit an OAuth flow issue: `run_local_server()` called `authorization_url()` before setting `redirect_uri`, causing a URL mismatch. Fixed by reverting to `flow.run_local_server(port=0)` (auto-browser-open) with the correct redirect URI auto-generated by the library.

### 6. Systemd Units — Backup

**Backup service** (`my_PC_backup.service`):

```ini
[Service]
Type=oneshot
User=pmpmt
WorkingDirectory=/home/pmpmt/.pi
Environment=BACKUP_INTERACTIVE=0
Environment=PYTHONPATH=.../backup_laptop_tool/src
ExecStart=.../backup_laptop_tool/.venv/bin/python -m backup_PC_tool.main
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/home/pmpmt
TimeoutStartSec=20min
```

**Backup timer** (`my_PC_backup.timer`):

```ini
[Timer]
OnBootSec=5min        # ← 5 minutes after each boot
Persistent=true       # Catch up if laptop was off during scheduled time
AccuracySec=1min
# No OnUnitActiveSec — runs once per boot, no recurring
```

Key difference from the VPS timer: no `OnUnitActiveSec` — the backup only fires on boot, not every N hours.

### 7. Systemd Units — Dashboards

Both dashboard services run continuously (boot → login → already running).

**Main dashboard** (`pi_main_dashboard.service`) — serves the landing page on port 3000:

```ini
[Unit]
Description=Pi Main Dashboard (Node.js on port 3000)
After=network-online.target pi_backup_dashboard.service
Wants=network-online.target pi_backup_dashboard.service

[Service]
Type=simple
User=pmpmt
WorkingDirectory=/home/pmpmt/.pi/html
ExecStart=/home/pmpmt/.nvm/versions/node/v24.18.0/bin/node server.mjs --port 3000
Restart=always
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=read-only
ReadWritePaths=/home/pmpmt
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
MemoryMax=256M
```

**Backup dashboard** (`pi_backup_dashboard.service`) — serves the backup UI on port 8765, proxied by the main dashboard at `/backup`:

```ini
[Unit]
Description=Pi Backup Dashboard (local web UI on port 8765)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pmpmt
WorkingDirectory=/home/pmpmt/.pi/apps-scripts/backup_laptop_tool
ExecStart=.../backup_laptop_tool/.venv/bin/python3 dashboard.py
Restart=always
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=read-only
ReadWritePaths=/home/pmpmt
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
MemoryMax=256M
```

Both use `ProtectHome=read-only` (not `true`) because the executables live under `/home/pmpmt`. `ReadWritePaths=/home/pmpmt` allows the backup tool to write config, tokens, and cache files. `Restart=always` with `StartLimitBurst=3` prevents restart storms while ensuring they come back up after crashes.

### 8. Web Dashboard

Created `dashboard.py` — a standalone Python HTTP server (no extra dependencies beyond stdlib and the venv). **Accessible at `http://localhost:3000/backup`** — proxied from port 8765 by `server.mjs` so users don't need to memorize additional ports.

**Proxy:** `server.mjs` forwards all `/backup/*` requests to `http://localhost:8765/*` (stripping the `/backup` prefix). The backup dashboard JS uses relative API paths (`api/settings` instead of `/api/settings`) so it works both behind the proxy and when accessed directly.

**Cards:**
- ⚡ **Actions** — "Run Backup Now" (triggers a manual backup), "Re-authorize Google" (OAuth re-auth)
- ⚙️ **Settings** — Drive folder name, retention count, hostname subfolder toggle, token status indicator
- 🚫 **Blacklist** — Read-only display of excluded directories with count badge ("X directories excluded from backup"), plus input to add new entries. Red-tinted tags for clarity; entries not individually removable from UI to prevent accidental deletion.
- 📋 **Last Run Output** — Colorized log viewer with refresh button

**Navigation:** `← Back to Dashboard` link in top-left corner returns to the main landing page (matching the Token Spend dashboard style).

**API endpoints:**
- `GET /api/settings` — read current backup settings
- `POST /api/settings` — save settings (writes to both `backup_config.json` and `.env`)
- `POST /api/backup` — trigger a backup, returns stdout/stderr/exit code
- `GET /api/log?lines=N` — tail the backup log file
- `POST /api/auth` — trigger interactive OAuth re-authorization

Settings changes are written directly to `~/.pi/agent/.env` (managed keys only — sensitive keys like `GOOGLE_CLIENT_SECRET` are never exposed or modified by the dashboard). Blacklist changes go to `backup_config.json`.

## Triggering a Backup

**Automatic:** 5 minutes after every boot (systemd timer)

**Manual:**
```bash
cd /home/pmpmt/.pi
PYTHONPATH=/home/pmpmt/.pi/apps-scripts/backup_laptop_tool/src \
  /home/pmpmt/.pi/apps-scripts/backup_laptop_tool/.venv/bin/python -m backup_PC_tool.main
```

**Dashboard:** Open `http://localhost:3000/backup` → click "▶ Run Backup Now"

**systemd:**
```bash
sudo systemctl start my_PC_backup.service
```

## Dashboard Integration

The backup dashboard is fully integrated into the main Pi Dashboard at `http://localhost:3000`:

- **Landing page** has a "Backup Tool" card (replaced the "Documents (coming soon)" placeholder)
- Card links to `/backup` which proxies to the Python dashboard on port 8765

## Results

After each successful run:
- A `.tar.gz` snapshot of `~/.pi` (excluding blacklisted directories, but **including** `~/.pi/agent/npm/node_modules/` for restore completeness) is created
- The archive is uploaded to Google Drive under `backups/pmpmt-ThinkPad-T15-Gen-2i/`
- Old Drive backups beyond retention count (5) are deleted
- Local cache is cleaned to keep only the most recent archive
- Logs are written to both journald and `backup.log`

The dashboard at `http://localhost:3000/backup` provides real-time settings management and manual backup triggering with no terminal needed.
